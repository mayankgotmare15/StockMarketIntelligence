# Coding Rules

- Read existing implementation before changing it.
- Follow the existing project architecture.
- Do not introduce a new framework when an existing solution is sufficient.
- Do not duplicate functionality.
- Reuse existing utilities and components.
- Keep changes scoped to the requested task.
- Do not modify environment variables or secrets unnecessarily.
- Never expose secrets, API keys, passwords, or tokens.
- Handle errors explicitly.
- Preserve backward compatibility unless breaking changes are requested.
- Test affected functionality after modifications.
- Do not claim a feature works without verifying it.
- Do not remove existing functionality unless explicitly requested.
