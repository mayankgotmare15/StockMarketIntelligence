- Always inspect existing code/files before modifying them.
- Never delete or overwrite existing functionality without a clear reason.
- Never invent information, results, configurations, APIs, metrics, or implementation details.
- Preserve existing architecture unless the user explicitly requests an architectural change.
- Make the smallest necessary change to accomplish the requested task.
- Check dependencies and related files before changing shared components.
- Do not assume that missing information is correct; verify it from the project.
- Never describe planned functionality as implemented.
- Never describe an experiment as completed unless it has actually been performed.
- After making changes, verify that the affected functionality still works.
- Keep related files consistent with each other.
- Do not modify unrelated files.
- Before destructive operations, clearly identify what will be changed or removed.
